# 4.0: clean native and Docker installs

Status: plan, 2026-10-16. Owner request: make spoond installable by
someone who is not us, natively and with Docker, and ship it as 4.0.

Progress, 2026-10-22: every slice (S1–S10) is on main, the module path
is `/v4`, and both installs pass on a fresh Debian 13 VM with nested
KVM (install, rerun as an upgrade, doctor, a named-snapshot round trip;
Docker also a drain across an orchestrator stop). Left for the release:
the tag; the ghcr image and base images (`write:packages`); the
deprecated-requests counter flat for two days; telling `grid` importers
about `/v4`. Release steps: `docs/runbooks/release.md`.

## Goal

A person with an x86-64 Linux host with KVM gets a working spoond with
one command, and can run that command again safely:

```bash
# native (Debian 13)
curl -fsSLO https://github.com/jrimmer/spoond/releases/download/v4.0.0/spoond_4.0.0_linux_amd64.tar.gz
tar -xzf spoond_4.0.0_linux_amd64.tar.gz
sudo ./spoond install --host-name sandbox.example.com --admin-key ~/.ssh/id_ed25519.pub

# Docker (any distribution with KVM and Docker)
docker compose -f compose.yaml run --rm prepare   # host settings; reboot if it says so
docker compose -f compose.yaml run --rm init      # config and secrets
docker compose -f compose.yaml up -d
```

## What makes installs hard today

1. No orchestrator or envd binary to download: you build the E2B fork,
   and envd has no written recipe.
2. Shipped files drifted from production (fixed on main 2026-10-16:
   drain hook paths, the gateway token flag, the missing dash unit), and
   `deploy/e2b/host-setup.sh` hard-codes 12288 hugepages behind a guard
   that fails once hugepages are reserved at boot.
3. Steps are spread over the README, `docs/install.md`,
   `docs/setup.md`, U04 and `deploy/PRODUCTION-ENV-2.7.md`.
4. Every secret is made by hand.
5. Host steps written down nowhere in this repo: the ZFS pool, the legacy
   iptables backend, the Docker AppArmor profile fix (see lacy-infra
   `docs/runbooks/sb-reinstall/GAPS.md`, which lists them all).

## Design

### R. Release artifacts

Every release attaches, besides the source:

| File | Contents |
|---|---|
| `spoond_<v>_linux_amd64.tar.gz` | the `spoond` binary |
| `spoond-runtime_<v>_linux_amd64.tar.gz` | `orchestrator`, `envd`, and `RUNTIME` (the fork commit and Go version they were built from) |
| `SHA256SUMS` | sha256 of both tarballs |

`deploy/e2b/RUNTIME` pins the fork commit (one line:
`e2b-runtime <full commit>`). `deploy/release/build-runtime.sh` checks
the fork out at that commit, runs its tests, builds both binaries
(`make -C packages/orchestrator build-local BUILD_ARCH=amd64`, and
envd's own Makefile `build` target) and writes the tarball and its
sha256. It runs in an `e2b-fork-worker` lease, so no host is touched.
Firecracker, the guest kernel and busybox stay on E2B's public bucket,
pinned by URL and sha256 (today in `host-setup.sh`; they move into the
installer's pin table).

The Docker image `ghcr.io/jrimmer/spoond:<v>` is built from the same
artifacts (D below). Publishing to ghcr needs a token with
`write:packages`.

### I. `spoond install` (native)

A new subcommand (`cmd/spoond/install.go`, build tag `!noinstall`) over
a new package `install/`. The shipped units and config templates are
embedded from `deploy/` through a small Go package there
(`deploy/embed.go`, `//go:embed`), so what the installer writes is
exactly what the repo ships.

Rules for every phase:

- Idempotent. A phase compares before it writes and reports each item
  as `created`, `changed` or `kept`.
- `--dry-run` prints the plan and changes nothing.
- Never overwrites a secret or env file that exists; it reports `kept`.
- Never prints a secret. Generated secrets go to 0600 files under
  `/etc/spoond`, and the report names the file.
- Every path is under a root prefix (`Root`, `/` in production) so unit
  tests run against a temp dir. Commands (apt, modprobe, sysctl, zfs,
  systemctl, docker) go through one runner interface that tests fake.
- Stops at the first failure with what to do next.

`spoond install` runs all phases in order; `spoond install <phase>`
runs one.

| Phase | Does |
|---|---|
| `check` | root; x86-64; `/dev/kvm`; memory ≥ 16 GiB; Debian 13 (other distributions warn); kernel ≥ 6.1; free ports 8890 8891 2222 8893 5000 5007 5008; the snapshot store has ≥ 100 GiB free |
| `host` | apt packages; modules (`nbd nbds_max=256 max_part=16`, `tun`, `kvm`) and the nbd udev rule; sysctls; hugepages (below); the legacy iptables backend; the snapshot store (below); Docker and the local registry (`registry:2.8.3` on 127.0.0.1:5000, `RequiresMountsFor` the store); the AppArmor Unix-socket check. Says when a reboot is needed |
| `runtime` | downloads `spoond-runtime_<v>` for the binary's own version (or takes `--runtime <tarball>`), checks `SHA256SUMS`; fetches the pinned Firecracker, kernel and busybox; installs `/etc/e2b/orchestrator.env`, `flags.json`, the token seed, the `e2b-guard` firewall and unit, the orchestrator unit; starts both; waits for `:5008/health` |
| `spoond` | installs its own binary as `/opt/spoond/spoond`; generates the secrets; writes `backend.env`, `dash.env` and the gateway env; TLS from `--tls-cert/--tls-key`, else a self-signed pair for `--host-name`; installs and starts backend, gateway, dash and drain; waits for `/healthz`; creates the first admin user from `--admin-key` |
| `images` | builds the image catalog: `--images minimal` (default: `py-base`, `go-base`), `all` or `none`. Base Docker images are pulled from `ghcr.io/jrimmer/spoond-images` when published for this version (R5), else built locally |
| `doctor` | `spoond doctor`; the install fails if doctor fails |

Hugepages: `--hugepages <pages>|auto`. `auto` keeps
`max(6 GiB, 17 % of memory)` for the host and reserves the rest in
2 MiB pages, both in `/etc/sysctl.d/90-e2b.conf` and on the kernel
command line (`/etc/default/grub`, `update-grub`), because a large pool
rarely allocates on a running host. 128 GiB reserves about 106 GiB; 16
GiB reserves 10 GiB.

Snapshot store: `--store-disk /dev/<disk or partition>` creates the ZFS
pool `forkdcache` (ashift 12, autotrim, lz4, atime off, xattr sa;
`zfs-dkms` from contrib, block cloning checked) with `forkdcache/e2b` on
`/forkdcache/e2b`. Without it, `--store-dir` (default `/forkdcache/e2b`)
must be an existing directory; XFS with reflink is recommended, and the
check phase warns about anything else.

The Forgejo runner is not installed by default (it needs a Forgejo URL
and registration token: `--runner-url`, `--runner-token`).

### D. Docker install

`deploy/docker/`: a `Dockerfile` (Debian 13 slim, the release artifacts,
Firecracker, kernel, busybox, nftables, iptables) and a `compose.yaml`.
The containers run privileged with host networking: this packages
spoond, it does not isolate it.

| Service | Does |
|---|---|
| `prepare` (run once) | `spoond install host --container`: writes the host's modules, sysctl, hugepages and grub settings through bind mounts of `/etc`, `/lib/modules` and `/sys`, and says when to reboot |
| `init` (run once) | `spoond install spoond --container --config-only`: writes config and secrets into `./config` |
| `registry` | `registry:2.8.3` on 127.0.0.1:5000, data in the store volume |
| `orchestrator` | loads the e2b-guard rules, runs the orchestrator; on SIGTERM runs `spoond drain --stop` first, and `spoond drain --start` once healthy |
| `spoond` | the backend, with the Docker socket for image builds |
| `gateway`, `dash` | the SSH gateway and the dashboard |

The host still needs KVM, reserved hugepages and the nbd module; that is
what `prepare` writes.

### R5. Published base images

`spoond images publish` (or a release script) pushes each base image of
`images/manifest.yaml` to `ghcr.io/jrimmer/spoond-images/<name>:<v>`;
`spoond images build --base-registry <prefix>` pulls instead of building
the Docker image. Templates are still built on each host.

### 4.0 itself

- Go module path `github.com/jrimmer/spoond/v4`. Importers of `grid`
  move when they upgrade; v3 stays available.
- `deploy/e2b/host-setup.sh` is removed (the installer replaces it).
- `docs/install.md` is rewritten around `spoond install` and Docker,
  with `docs/setup.md` folded in; U04 stays as design history.
- The surfaces deprecated for 4.0 go (#139; owner decision 2026-10-16):
  the `/api/sandboxes` path alias (routes register under `/api/leases`,
  the alias rewrite and its deprecation counter go), keyless LLM access
  under `LLM_OPEN_LEGACY` (the setting becomes unknown; a keyless
  identity-user owner always gets `401`), and the `hold_ttl` field
  accepted and ignored since 3.0. The last callers of the alias were
  agent-hub's pool scripts, moved to `/api/leases` on 2026-10-16
  (agent-hub 8750539); the release waits for
  `spoond_deprecated_requests_total` to stay flat for two days.
  Production drops `LLM_OPEN_LEGACY` from `backend.env` in the 4.0
  window.

### Testing

Unit tests run every phase against a temp root with a fake command
runner. The real test is a fresh Debian 13 VM with nested KVM, run as a QEMU
guest on sb (nested virtualisation is on; QEMU goes on with the
2026-10-18 reinstall), its memory backed by hugepages from spoond's pool
for the length of the test: native
install from a release candidate, `spoond doctor`, a lease, a named
snapshot round trip; then the same with Docker. The release waits for
both.
