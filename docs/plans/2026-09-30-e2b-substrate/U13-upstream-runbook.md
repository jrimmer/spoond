# U13 — Upstream tracking runbook

## Purpose

Keep the fork current with E2B safely, at most once a month, gated by the
conformance suite. Write the procedure as `docs/runbooks/e2b-upgrade.md` in
the spoond repo, with the exact content below, and perform it once to prove
it.

## Preconditions

U12 is done.

## Facts relied on

- **Fork branches** (U03): `upstream` (pristine) and `spoond` (upstream plus
  patches P1–P5 and the docs commits).
- **Protos:**
  - spoond keeps unmodified copies of five protos in
    `substrate/e2b/proto/`, generated by `substrate/e2b/gen.sh` (U06);
  - `substrate/e2b/proto/SOURCE` records the fork commit.
- **Versions:** each build records its `firecracker_version` and
  `kernel_version`. The orchestrator picks binaries by those versions from
  `/fc-versions/<v>/amd64/` and `/fc-kernels/<v>/amd64/` (A3 A4). A snapshot
  can only be restored with the Firecracker line that wrote it.

## `docs/runbooks/e2b-upgrade.md` (write exactly this procedure)

1. **Pick a target.** Take the newest upstream commit on `main` that is at
   least 7 days old. A tag is preferred when one exists.
2. **Update `upstream`** (on the host, in `/root/src/e2b-runtime`):
   ```bash
   git fetch github
   git checkout upstream && git merge --ff-only <target>
   git push origin upstream
   ```
3. **Rebase the patches:**
   ```bash
   git checkout spoond && git rebase upstream
   ```
   - Resolve conflicts **only** within the patch's own purpose (see
     `PATCHES.md`).
   - If upstream now provides a patch's behaviour, drop the patch, and note
     it in `PATCHES.md`.
4. **Regenerate** with the U03 command (step 2). If `git status` shows
   changes in generated files that are not explained by our proto
   additions, STOP.
5. **Run the fork unit tests:**
   ```bash
   cd packages/orchestrator && go test ./pkg/startupreclaim/... ./pkg/tcpfirewall/...
   cd ../shared && go test ./pkg/featureflags/...
   ```
6. **Diff the contract.** Copy the five protos into spoond's
   `substrate/e2b/proto/` and run `substrate/e2b/gen.sh`.
   - `go build ./... && go test ./...` in spoond must pass.
   - Any changed field that spoond sets (U06 Facts list) must be reviewed:
     note every change in the upgrade's commit message.
7. **Build** the binaries (U03 step 9), then **stage** them without
   replacing the live ones:
   ```bash
   install -m 0755 /root/src/e2b-runtime/packages/orchestrator/bin/orchestrator /usr/local/lib/e2b/orchestrator.next
   install -m 0755 /root/src/e2b-runtime/packages/envd/bin/envd /fc-envd/envd.next
   ```
8. **Check the artifact pins.**
   - If upstream's default Firecracker or kernel version changed
     (`embed/compose/.env` and `flags.go`), fetch the new versions **in
     addition to** the old ones, following U04 step 5. Take the SHA-256s
     from `embed/compose/scripts/fetch-artifacts.sh`.
   - **Never delete** a `/fc-versions/<v>` or `/fc-kernels/<v>` directory
     while any row in `builds` (state ≠ `deleted`) references that version.
     Get the versions in use from `/opt/spoond/spoond doctor` (check 7
     prints them; see the addition below).
   - Set `DEFAULT_FIRECRACKER_VERSION` and `DEFAULT_KERNEL_VERSION` in
     `/etc/e2b/orchestrator.env` to the new versions **only** in step 10.
9. **Swap and validate** (Autonomous window, `00-README.md`; steps 9–10):
   - **Rollback artifacts**, checked by protocol step 1:
     - `/usr/local/lib/e2b/orchestrator` (current) and `/fc-envd/envd`
       (current), both copied to `.prev` in 9.3 before the swap;
     - `/etc/e2b/drain.env`, copied to `/root/drain.env.pre-upgrade` first.
   - **Rollback commands:** the "If it fails" block in step 10, then restore
     `/root/drain.env.pre-upgrade` to `/etc/e2b/drain.env`.
   - **On any failure** in 9–10: rollback, `window_smoke`, then `BLOCKED`
     (protocol step 4).

   1. After `window_idle` returns 0, stop the production runner:
      `systemctl stop spoond-runner` (protocol step 3). Then
      `cp /etc/e2b/drain.env /root/drain.env.pre-upgrade`.
   2. Re-create staging (its unit files and `/etc/spoond-staging/` were kept
      by U12 step 20; `staging.db` and the binary were not):
      ```bash
      export PATH=/usr/local/go/bin:$PATH
      cd /root/src/spoond && git fetch && git checkout main && git pull --ff-only
      install -d -m 755 /opt/spoond-staging
      go build -o /opt/spoond-staging/spoond ./cmd/spoond
      rm -f /var/lib/spoond/staging.db*
      systemctl enable --now spoond-backend-staging spoond-sshd-gateway-staging
      ```
      If staging has any lease (a leftover), delete it through its lease API
      before continuing.
   3. Point the drain at **both** backends, production first (the drain CLI
      accepts comma-separated lists, U10):
      ```ini
      SPOOND_DRAIN_URL=https://127.0.0.1:8890,https://127.0.0.1:18890
      SPOOND_ADMIN_TOKEN_FILE=/etc/spoond/admin-token,/etc/spoond/admin-token-staging
      SPOOND_DRAIN_INSECURE=1
      ```
   4. Swap in the `.next` binaries and restart. The drain pauses every
      production lease and resumes it after the restart:
      ```bash
      mv /usr/local/lib/e2b/orchestrator /usr/local/lib/e2b/orchestrator.prev
      mv /usr/local/lib/e2b/orchestrator.next /usr/local/lib/e2b/orchestrator
      mv /fc-envd/envd /fc-envd/envd.prev
      mv /fc-envd/envd.next /fc-envd/envd
      systemctl restart e2b-orchestrator
      curl -fsS http://127.0.0.1:5008/health
      ```
   5. Build the staging catalog with the new orchestrator:
      ```bash
      cd /root/src/spoond && SPOOND_DB_PATH=/var/lib/spoond/staging.db /opt/spoond-staging/spoond images build --all --manifest images/manifest.yaml --context images
      ```
   6. Run the conformance suite against staging (the U08/U09 staging
      settings) with `CONFORMANCE_DESTRUCTIVE=1` and `-skip '^TestR2_'`.
      R2 (a SIGKILL of the shared orchestrator) is not run here: it would
      also kill production leases. R1 is safe because the drain covers both
      backends.
10. **Promote** if the suite passes:
    - keep the new binaries: `rm -f /usr/local/lib/e2b/orchestrator.prev /fc-envd/envd.prev`;
    - rebuild all production images:
      `cd /root/src/spoond && SPOOND_DB_PATH=/var/lib/spoond/spoond.db /opt/spoond/spoond images build --all --manifest images/manifest.yaml --context images`,
      so new sandboxes use the new Firecracker and kernel;
    - point `/etc/e2b/drain.env` back at production only (U12 step 10
      values);
    - disable staging and drop its catalog:
      `systemctl disable --now spoond-backend-staging spoond-sshd-gateway-staging && rm -f /var/lib/spoond/staging.db*`;
    - `systemctl start spoond-runner` (protocol step 5);
    - run `window_smoke` against production; it must return 0.

    **If it fails:** restore the previous binaries and restart, then do the
    same drain, staging and runner steps as on success:
    ```bash
    mv /usr/local/lib/e2b/orchestrator /usr/local/lib/e2b/orchestrator.next
    mv /usr/local/lib/e2b/orchestrator.prev /usr/local/lib/e2b/orchestrator
    mv /fc-envd/envd /fc-envd/envd.next
    mv /fc-envd/envd.prev /fc-envd/envd
    systemctl restart e2b-orchestrator
    ```
    Then restore `/root/drain.env.pre-upgrade` to `/etc/e2b/drain.env`,
    disable staging as on success, `systemctl start spoond-runner`, and run
    `window_smoke`. Record the failure in `PATCHES.md` under "Upgrade
    attempts", and write `BLOCKED-U13.md`.
11. **Record:** update `PATCHES.md` ("Current build": the commit and
    SHA-256s) and `substrate/e2b/proto/SOURCE`. Commit both repositories.
12. **Upstream the patches:** for each patch still carried, open or refresh
    an upstream PR where it makes sense, and link it in `PATCHES.md`.

## Addition to `spoond doctor` (for step 8)

Doctor check 7 also prints the distinct `firecracker_version` and
`kernel_version` values of non-deleted builds, as
`versions in use: fc=[...] kernel=[...]`.

## Commits

Make commit 2 before performing the runbook once (step 8 uses it).

1. `docs(runbook): E2B upgrade procedure`
2. `feat(doctor): list Firecracker and kernel versions in use`

## Done when

The runbook exists, and one real upgrade (or a dry run to the same base
commit) has been performed with it and recorded in `PATCHES.md`.
