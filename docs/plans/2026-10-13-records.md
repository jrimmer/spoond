# Records panel (owner-approved 2026-10-13)

The dashboard gets a "records" panel of all-time stats. Spoond deletes a
lease's row when it ends, and the backend journal rotates (about 1 GB,
reaching back only to 2026-10-09), so the records need a durable lease
history first.

## Part A — backend: lease history (store + api + cmd/spoond)

Migration `0029_lease_history.sql`:

```sql
CREATE TABLE lease_history (
  lease_id     TEXT PRIMARY KEY,
  owner        TEXT NOT NULL,          -- owner id (u-…) or legacy consumer name
  image        TEXT NOT NULL,
  memory_mb    INTEGER NOT NULL DEFAULT 0,
  created_at   TEXT NOT NULL,          -- RFC 3339 UTC
  ended_at     TEXT NOT NULL,          -- RFC 3339 UTC
  outcome      TEXT NOT NULL CHECK (outcome IN ('released','lost')),
  reason       TEXT NOT NULL DEFAULT '',
  peak_mib     INTEGER NOT NULL DEFAULT 0,  -- 0 = never measured
  start_ms     INTEGER NOT NULL DEFAULT 0,  -- create-to-grant latency; 0 = unknown
  start_kind   TEXT NOT NULL DEFAULT '',    -- the lease's Start (warm/cold/…); '' = unknown
  max_nap_secs INTEGER NOT NULL DEFAULT 0   -- longest suspend→resume; 0 = none/unknown
);
CREATE INDEX lease_history_ended ON lease_history(ended_at);
ALTER TABLE leases ADD COLUMN start_ms INTEGER NOT NULL DEFAULT 0;
ALTER TABLE leases ADD COLUMN suspended_at TEXT NOT NULL DEFAULT '';
ALTER TABLE leases ADD COLUMN max_nap_secs INTEGER NOT NULL DEFAULT 0;
```

- **Write a row when a lease ends:** at release (outcome `released`, with
  the release's peak and reason) and when it is marked lost (outcome
  `lost`). `INSERT OR IGNORE`, so a lost lease's later release does not
  overwrite it. A failed write is logged and never fails the release.
- **start_ms:** the create path's existing `time.Since(start)` at grant
  (the value LeaseGrantDur observes), stored on the lease row.
- **Naps:** set `suspended_at` when a lease suspends (every suspend path:
  idle, drain, take-back). On a successful resume, update
  `max_nap_secs` to the larger of itself and now − suspended_at, and clear
  `suspended_at`. A lease released while suspended does not count that
  final sleep as a nap.
- **Import:** `spoond history import` reads `journalctl -o
  short-iso-precise` lines on stdin and pairs each `lease journal:
  op=create` with the same lease_id's `op=release` or `op=lost`. The
  timestamp is the line's first field. It inserts `INSERT OR IGNORE` rows
  (peak from `peak_mib=`, memory from `memory_mib=`; start_ms, start_kind,
  max_nap_secs stay 0/''). Unpaired lines are skipped. It prints
  `imported N, skipped M` and is safe to run twice. It opens the DB like
  the other offline subcommands (the backend may be running; SQLite WAL).
- Docs: operations.md (the table and the import), CHANGELOG Unreleased.

## Part B — dashboard: records panel (cmd/spoond-dash)

- Read `lease_history` plus live `leases` rows (read-only DB, as the
  collector already does). Recompute at most once a minute and cache the
  result; the 2 s refresh reuses it. If the table is missing (an older
  backend), the panel shows "no history yet".
- **Excluded owners:** `DASH_RECORDS_EXCLUDE`, a comma list of owner
  NAMES, default `conformance,test-consumer`. Map ids to names with the
  collector's existing `userNames()`. Excluded leases count nowhere in
  the panel. The images "uses" column is untouched.
- **The records,** over history rows plus live leases (a live lease's
  end is now):
  - busiest: the most leases running at once, and when it first reached that.
  - one image: the most leases of one image at once: image ×N, when.
  - longest run: the longest ended_at − created_at: duration, image, start date.
  - shortest run: the shortest **released** lease that ran ≥ 1 s: duration, image, start.
  - top owner: the owner name with the most leases, and the count.
  - lifetime: lease count · total lease-hours · total memory GiB-hours (memory_mb × hours / 1024); use k for thousands (1.6k).
  - busiest day: the most leases created on one Pacific calendar day.
  - biggest fleet: the most leases one owner had running at once: owner, N, when.
  - most memory: the largest peak_mib, as GiB with one decimal: image, end date.
  - no losses for: whole days since the newest `lost` row, and its date/time; "no losses yet" if none.
  - longest nap: the largest max_nap_secs: duration, image. "— (counting from 3.8)" while none > 0.
  - fastest start: the smallest start_ms > 0: "41 ms · image · date". "— (counting from 3.8)" while none.
- **Formats:** times in America/Los_Angeles as `M/D h:mma` (`10/12 1:28a`); a
  date alone as `M/D`. Durations: `<1 s` → `N ms`, `<1 m` → `Ns`, `<1 h` →
  `Nm Ns`, `<1 d` → `Nh Nm`, else `Nd Nh`. Footer: "since <first created_at
  M/D> · test leases not counted" (drop the second clause when the exclude
  list is empty).
- The sweep for "at once" records: sort start (+1) and end (−1) points,
  with ends before starts at equal times.
- Tests: unit tests for each record on a small fixture, plus golden files
  at 104 and 72 (`go test ./cmd/spoond-dash -run TestGolden -update`).
